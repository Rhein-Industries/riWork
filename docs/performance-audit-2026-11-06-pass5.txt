One guarded persistence owner per layout session
CurrentLayout generations share Arc<OwnedPersistence>. Registration and a
successful project switch create one owner; ordinary publications clone only
its Arc. Discarding intermediate generations no longer submits disposal work.
The final owner transfers its backend Arc to the existing blocking/fallback
disposal path. A delayed ArcSwap reader retains the same guarded owner, and
old/new projects retain distinct owners across a switch. This does not use
racy strong-count tests. Close admission, cancellation, explicit flush and
fallback-on-runtime-shutdown behavior are unchanged.

Terminal reply ownership
The existing validated shell.output response construction is now a private
helper. It moves the parsed output String into the full response or, when an
accepted delta replaces the full response, into the retained screen. A full
reply that also updates the cache still needs two owners and performs one
string clone. Compared with the previous builder, one full-screen clone is
removed on each path: plain 1 -> 0, accepted delta 1 -> 0, remembered full reply
2 -> 1. This is payload allocation accounting, not all response allocations.

Request validation, CLI calls/capping, hash/unchanged/error handling, SGR
validation, screen/scrollback metadata, delta profitability, response field
order and device/question/cache limits are preserved. Early extraction changes
only the local JSON output slot; metadata validation receives the same text.
Independent review found no observable response or cache-lifecycle change.

Measurement limits and remaining work
The disposal benchmark includes layout payload destruction and waits for the
final fake-backend destructor, so deferred releases cannot escape its timing.
It excludes generation construction/publication and actual persistence I/O.
The candidate includes real HostLayout/ArcSwap teardown while the baseline
models the prior retained CurrentLayout ownership; that small asymmetry favors
the baseline. Layout payload deallocation still occurs on the final reader's
thread. The producer channel remains unbounded.

The terminal reply benchmark begins with parsed JSON and excludes CLI capture,
JSON parsing, transport, response encoding and UI rendering. Full responses
also retained by the cache still clone once; validation and delta comparison
still scan text. Neither benchmark establishes end-to-end latency or application
CPU usage. Files DTO construction, cold/overflow search, unfinished Markdown,
rendering, memory growth and representative release/UI verification remain open.

  target/performance-audit/files-deferred-dto-plan.txt and

precedence as a compatibility requirement: defer owned DTO strings, retain

No Files DTO implementation or timing gain is claimed in this pass.
