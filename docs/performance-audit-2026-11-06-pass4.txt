Empty terminal maintenance
The terminal worker previously woke every 250 ms even with no live terminal
components. It now waits for the next configuration or pooled-surface deadline
when empty. A generation-based Condvar wakes it for a new registration or an
earlier pool deadline without losing notifications between inspection and wait.
Live components, queued main work and a coalesced config change retain the
existing 250 ms polling bound. Later pool deadlines may cause an earlier harmless
wake; they do not need to interrupt the worker. Lock acquisition does not add
background AppKit access or hold the registry during I/O.

The deterministic ten-minute schedule test changes 2,400 empty-registry wake-ups
to 300 while preserving all 300 configuration checks. Startup, queued work,
registrations and pool events can add wakes. This is scheduling evidence, not
an application CPU/power measurement. Notification-before-wait, notification
across the wait boundary, timeout, pending config and deadline-selection tests
pass along with existing terminal policy/config/registry tests: 34 passed,
1 opt-in benchmark ignored. Independent review found no lost-wake, deadline or
lock-order issue.
Evidence: target/performance-audit/terminal-empty-wake-results.json,

Shared native hub deliveries
Each published payload is now allocated once and shared by the cache, listener
queues and posted callbacks. The public owned Snapshot<T>/recv() API remains
available; typed JS callbacks serialize a borrowed shared payload with the same
wire shape and declarations. Publication no longer deep-copies T for each
listener. Checked revisions, equality suppression, atomic initial subscription,
capacity 64, overflow resync and close semantics are preserved. Delivery merges
resync flags and consumes at most 64 queued envelopes, so continuous publication
cannot monopolize an engine turn.

Desktop snapshot batches
The host service consumes up to 32 adjacent snapshots and materializes only the
latest. Every non-snapshot command remains a FIFO barrier, including Wake and
shutdown commands. Initial restoration uses the first snapshot's window IDs;
the latest captured generation/focus/loading/global data survives. A lazily
allocated frame map retains each window's last valid ordinary size even if a
later capture is maximized/fullscreen or invalid. Fresh settings and close
admission checks still gate remembering frames. Progress and runtime ticks run
between bounded batches. Isolated snapshots do not allocate that frame map.

Large search previews
Cold searches still serialize tool input once with the canonical pretty JSON
serializer before normalization. On a warm hit, sufficiently large/costly JSON
can remain borrowed while a prefix formatter emits only the requested preview.
It uses serde's PrettyFormatter and canonical escaping of bounded UTF-8 string
chunks; it does not implement a separate escape table. Ordinary small inputs
keep normal formatting; distant JSON offsets above 8192 characters use the full
serializer. Unexpected prefix-writer errors fall back to canonical formatting.
Late ASCII text previews skip validated ASCII prefixes by byte offset. Unicode
uses the standard character iterator. Cache shape, 8 MiB/4096-entry budgets,
admission, invalidation, cancellation checkpoints, contextual lowercase and
original character-offset/whitespace behavior are unchanged.

Remaining work
The application-wide goal is active. Concrete remaining costs include:
* Every retained layout generation owns a separate persistence disposal guard.
  Releasing old generations can submit redundant blocking tasks or spawn OS
  threads although the backend remains in use. One shared guarded owner per
  backend session can remove those intermediate submissions while preserving
  final off-thread destruction, cancelled switches and delayed readers.
* The host producer queue remains unbounded. Snapshot-tail coalescing must use
  the ordering of all service senders, preserve command barriers/initial restore
  IDs/valid ordinary geometry, and avoid moving deep generation destruction
  onto AppKit. A global latest-value slot alone does not preserve that ordering.
* Remote shell output is parsed into an owned JSON string, then copied into its
  retained screen and/or response. Moving the original string can eliminate a
  full-screen copy without changing delta profitability or wire metadata.
* Files creates full absolute/relative path DTO strings for every scanned entry
  before retaining only the displayed prefix. Enumeration metadata syscalls,
  path safety, exact natural ordering and omitted/error semantics need to stay
  intact if that construction is deferred.
* Cold/budget-overflow search normalization, distant JSON matches, owned plan/
  todo/file-change formatting, very large unfinished Markdown tails, rendering,
  memory growth and representative release/UI measurements remain open.
The parser harness, helper benchmarks and targeted suites do not prove full
application performance or a clean full-workspace test suite. Prior baseline
failures remain documented in earlier reports.
