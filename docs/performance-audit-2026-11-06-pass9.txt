RiWork / Somtus performance audit — ninth pass, 2026-11-06

Scope
Prepared independently while pass8's host queue was reviewed and validated.
The broad performance goal remains active. No desktop interaction, installed-app
restart, external service or user-data fixture is involved. Somtus cua-driver
remains the required provider for any future desktop automation.

Bounded remote screen validation — adopted
screen_fields only needs to establish that output has at least the declared
number of screen rows. It now counts at most that many str::lines items,
avoiding a scan through all remaining scrollback. It preserves the same iterator,
scalar validation order, zero/invalid dimensions, existing cursor behavior and
metadata construction. Styled output validation still scans the complete text.
This is one localized expression change; prior remote ownership/cache work stays
intact. No new persistent cache or response policy is introduced.

Both optimized and opt-level 0 helpers pass 12,937 validator comparisons and 996
complete reply/cache-follow-up comparisons. Coverage includes LF/CRLF/lone CR,
Unicode, trailing lines, zero/u32::MAX bounds, malformed or missing fields,
styled/plain output, deltas and base hashes. Actual current output_reply and
output_delta code is used. Independent semantic/extraction review is clean.

Measurements retain all 48 conditions in each profile, seven chronological
alternating pairs each. Values below are median batch-average microseconds per
non-delta full reply, including response destruction:
  Returned/required ASCII lines       optimized          helper opt-level 0
  1/1                                 2.477 -> 2.496      6.320 -> 6.216
  24/24                               2.735 -> 2.766      7.526 -> 7.660

  540/24                              8.535 -> 2.816     42.703 -> 7.776

Tiny/visible-only controls are approximately flat. Full scans of too-short output
show small mixed changes: optimized ASCII 2,000/2,001 increases 0.772 us (+3.27%),
and helper opt-level 0 ASCII 24/25 increases 0.159 us (+3.41%). The largest absolute
control shift is styled 2,000/2,001 at opt-level 0: +35.401 us (+1.33%). Styled
excess-history replies improve much less because SGR validation remains dominant.
All controls and raw samples are retained; no universal improvement is claimed.

Timed full replies use delta=false/base=None; cache updates and diff polling are
covered by proof, not these timings. Input Value cloning/setup is excluded, and
unused Held teardown is outside both variants. Both helper profiles use the same
cached optimized sorted-map serde_json dependency, so opt-level 0 is not a whole
Debug-process measurement. CLI launch, request parsing, network, UI and allocator
counts are outside scope. Runs took 0.924/6.025 seconds without competing owned
jobs; ordinary desktop activity was uncontrolled.
