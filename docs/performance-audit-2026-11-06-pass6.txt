Shared preference reads
SettingsBackend has an additive get_shared() method whose default adapts the
existing owned get(). CoreSettingsBackend uses the already-established shared
SettingsStore generation. PreferenceService retains that Arc and captures it
together with its error under the same state mutex. Read-only DTO construction
can then run outside the lock. Writes/publication stay serialized, failed reads
retain the old generation, and failed writes still leave state/error unchanged.
Owned get() callers and older backend implementations remain compatible.

Appearance previews resolve an explicit temporary theme against borrowed saved

maps are not copied or mutated. Usage's selected-account read uses the shared
cache and clones only the selected account string. Project settings and saved
appearance publication retain immutable generations through their existing
background work. No cache freshness or subscription policy changed.

Files enumeration
Enumeration retains compact name/lowercase/kind/index records, then builds owned
absolute/relative/kind DTO strings only for the displayed prefix. Each successful
entry still performs the original path checks before sorting, even if later
omitted. Hidden/UTF-8 filtering, scan limits, omitted counts, descriptor-relative
fstatat with no-follow, natural/directory/stable ordering, displayed file identity
opens and lazy Git decoration are preserved. Raw-name tie comparison is confined
to records from the same parent, where it equals joined-path ordering.
One scratch PathBuf retains capacity across per-entry checks. Displayed paths
reuse prefixes obtained from the first checked selected child; this preserves
raw path spelling, repeated separators and UTF-8 boundaries while avoiding
another path check/allocation for every displayed record. Empty and zero-limit
results still perform no selected-child check. The caller confines the parent
at or below the root, and real directory names are single non-dot components,
so both checked child strings end with the selected name. The returned vector
reserves exactly the displayed length.

APFS rejects invalid-UTF-8 filenames at fixture creation. Portable raw-byte
name/path helper tests therefore run on macOS; the full invalid-UTF-8 parent/
empty/all-skipped filesystem test is retained for other Unix filesystems. That
real-filesystem coverage is not claimed on macOS. The existing ancestor swap,
symlink and special-file identity safety checks remain part of verification.
Final-source validation passes 18 Files unit tests (1 ignored benchmark) and
3 files_bridge tests. Exact-helper comparison covers 12,216 path/error/limit
cases, 16 construction allocation/parity cases and four real full-listing
allocation/parity cases. Metadata and selected-file identity call counts match.
Independent review found no ordering, error-precedence, confinement, cleanup or
raw-path compatibility issue. Final timing results are recorded below.

Markdown rule classification
is_rule no longer builds a Vec<char> before rejecting ordinary prose. It retains
the same indentation/Unicode-whitespace/three-identical-markers contract and
rejects non-marker or mismatched characters immediately. Parser caching, block
conversion, Splice format and rendering behavior are unchanged. An optimized
probe of exact parser/converter sources verifies 271,458 rule cases, 449 UTF-8
stream prefixes with parsed/document/serialized-Splice parity and 25 threshold
cases before adoption; a focused production regression test is added.
