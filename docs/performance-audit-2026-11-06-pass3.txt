Shared immutable Store and Settings generations
ParseCache<T> now retains Arc<T>. Store::snapshot_shared() and
SettingsStore::load_shared() return immutable generations. Existing owned
snapshot()/load() APIs still return independent copies, cloned after releasing
the cache mutex. Successful State transactions move the committed value into
the cache; Settings prepares its required owned-return/cache copy outside the
mutex. The host's five read-only Store/Settings paths use the shared APIs.

The existing FileStamp contract is unchanged: length, mtime, Unix inode,
missing-file vs metadata-error distinction, before/after read checks and
successful-write-only cache publication. In particular, an in-place edit that
restores size/mtime intentionally retains the cached value, as before; an
atomic replacement with a new inode refreshes it. New tests cover generation
sharing, old snapshot retention, independent owned/COW mutation, failed writes,
invalid JSON, disappearance, atomic replacement and metadata errors.

Main-thread window capture
Window launch DTOs are held in Arc. An ordinary Service::Snapshot captures
shared launch/current-layout generations plus geometry and focus; the service
thread creates the owned reload DTO. Capture preserves the generation observed
before handoff even if a layout or global selection changes afterward.
Materialization builds the final DTO directly instead of cloning and discarding
the launch layout. Closing one window selects it before capture. state("")
updates every window before one publication; open/dev-reload avoid duplicate
publication. Existing close admissions, flush barriers, loading fallbacks,
project-path freshness, and global-state merging remain in force.

Four loaded windows formerly cloned eight layouts on AppKit per publication.
They now clone zero there and four on the service thread. A selected close
copies one current/fallback layout instead of eight across all four windows.

Debug medians of three paired samples, each 100 captures, four windows:

Transcript search text ownership
Search now borrows simple body text and represents command/tool output with
borrowed segments. Warm hits construct only the bounded preview, without
copying the full output. Ordinary user text can borrow its trimmed slice;
CR/attachment cases retain the previous normalization. Owned item_text callers
still receive the same strings. Lowercase remains the standard whole-string
operation, preserving expanding mappings and contextual Greek sigma. Preview
offsets retain the old lowercase-character-count behavior and whitespace rules.
Cache limits, touched-position invalidation, hit ordering/200-hit cap and latest
search cancellation remain in force. Cancellation checks surround the work for
each item; one huge item still cannot be interrupted midway through formatting.

Native project inventory
Inventory search uses snapshot_shared(), avoiding a copy of all tasks, trees
and project memos before each query. SearchHit DTOs remain independently owned.
Recency dates join against their existing BTreeMap instead of scanning every
project for every date. Small inventories and sparse date maps use the exact
old scan; larger joins move original keys/values with remove_entry and stop
once no dates remain. Duplicate/missing/reordered project IDs preserve the same
sorted map. An initial generic iterator version regressed sparse maps and was
replaced with the concrete ProjectDto slice path before final validation.

Remaining work
The application-wide objective remains active. Concrete next targets include:
* Hub<T> publication deep-clones each full payload per live listener under its
  mutex. Each listener queues up to 64 owned snapshots; latest() often discards
  most before JS delivery. Shared internal payloads could remove wasted copies,
  but must preserve revision/resync/overflow/close behavior and avoid shifting
  a large delivered-value clone onto an engine thread. Public owned recv()
  callers and custom delivery loops need explicit compatibility coverage.
* The host service materializes every queued geometry snapshot. Coalescing must
  preserve ordering around ready/open/close/quit/restart barriers.
* Search still formats very large tool input JSON on warm hits and scans long
  prefixes for late previews. File-change/plan/todo formatting remains owned.
* Initial Ghostty theme projection writes configuration and invokes its
  main-thread parser before the first AppView. Moving this requires startup
  measurements and preservation of the initial palette and native ownership
  rules; no startup change or measured startup gain is claimed here.
* Very large unfinished Markdown tails, file enumeration, memory growth,
  rendering, transport and representative release/UI measurements remain open.
Prior broad engine/workspace baseline failures remain documented in pass one;
targeted passing checks do not establish a clean full-workspace suite.
