Terminal maintenance
The worker now releases the terminal registry mutex before configuration I/O or
model locks. Configuration polling caches the discovered dependency graph and
stats known files; changed identity/mtime/ctime/size, resolver environment,
creation/deletion, read failures or a five-minute rescan trigger discovery.
Missing optional paths remain watched. Config and theme parsing limits remain.
The main-queue gate coalesces pending passes, preserves configuration changes,
and dispatches for model changes or actual release/retry/pool deadlines.
Native view reparenting emits an internal placement revision so moving between
windows invalidates release grouping without reading AppKit from the worker.

Native transcript allocation and search
Streaming Markdown now keeps stable blocks in place when uniquely owned and
retains copy-on-write behavior for external snapshots. It copies/scans only the
changed source suffix after verifying the stable prefix. CR/BOM replacements
retain the full-parse fallback. Body building and streaming updates borrow the
folded item/text instead of cloning the full message first.
Search lazily caches exact Unicode lowercase text by stable item position,
bounded to 8 MiB of string capacity and 4,096 entries. Accepted folds invalidate
every touched position; replacements/deltas remain fresh. Search order, the
200-hit limit and original Unicode preview semantics are preserved.

Engine replay and nested projection
Replay buffers normalized events in its existing input allocation before writing
to subscribers. Known
event normalization and unknown/future wire bytes are retained. Owned parsed
item events move into the transcript instead of cloning their large payloads.

counts activity in one pass. A bounded scan avoids hashing overhead on small
activity summaries; larger summaries use indexed raw parent membership.

Find cancellation and worker progress
Find opts into searchLatest/cancelSearch while ordinary search keeps its original
promise/result behavior. Each handle retains one pending query; newer queries
settle superseded pending requests as null and cancel active scanning between
items. Lightweight queue tickets preserve ordering with transcript events and
ordinary worker operations. Cancelled tickets do not split event folding batches.
Result publication and cancellation share a short lock, preventing a cancelled
generation from subsequently publishing its hit list. Closing the handle also
cancels outstanding Find work. The UI cancels on input changes, close and cleanup.
The worker drains at most 1,024 messages/events per pass, preserving entire feed
batches, so continuous producers cannot postpone folding/delivery indefinitely.
This does not bound the transport queue or interrupt work inside one large item.
