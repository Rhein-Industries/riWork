Borrowed Markdown lines
The preceding phase probe identifies open multiline fences as a remaining parse
cost. The accepted candidate normalizes tabs once into Cow<str>, borrows source
lines and recursive list/quote slices, and preserves owned returned blocks.
Tab-free source remains borrowed; tabs still expand to exactly four ASCII spaces.
Unindent retains the original calculation and returns a slice. MAX_DEPTH, task
markers, CR/BOM behavior, parser/cache decisions and the Splice wire format are
unchanged. Cache byte offsets still use the original source. Baseline is the
pass6 parser, including its accepted allocation-free is_rule predicate.

Independent review found no lifetime or semantic blocker. The exact-source
optimized probe verifies 205 source cases through 8,968 UTF-8 stream prefixes,
including full/cached parse, converted document and serialized Splice parity;
1,170 unindent cases; 24 large inputs; replacements and 205 retained parsed-Arc
cases. The preceding rule/stream/threshold proof also passes. Allocation counters
run in a separate executable with 48 exact-output comparisons.

Five alternating paired samples of 32 appended updates across 24 workloads
(nominal 16/64/256 KiB starting sizes; 256-byte chunks) measure parse, update
and combined update+serialization separately, 72 conditions total. The optimized
helpers use the pinned release dependencies recorded in provenance. Input setup
is excluded. These are in-process helper measurements, not UI latency.
Combined multiline-fence updates improve 39–48% across tab-free, sparse-tab and
all-tab fixtures. At nominal 256 KiB starting size, median batch-average costs

  No tabs: 1,120.886 -> 612.691 us;

Frontend Markdown splices
The accepted frontend change keeps the existing prefix slice and concat,
then avoids the final slice only when the new array already has exactly the
requested length. It preserves the fallback for all other slice lengths.
18,295 differential QuickJS cases pass, including frozen/sparse arrays, numeric
boundaries, mixed multiple splices, retained object identities and read/key order.
Separate operation counts show valid tail-splice arrays fall from three to two.
For a tail rewrite of N blocks, copied result-length totals fall from 3N-1 to
2N-1. These are instrumented builtin calls/lengths, not allocator bytes or RSS.

Nine alternating paired samples of actual full bodyChanges helpers in the
cached release QuickJS runtime, reusing decoded inputs and normal uninstrumented
Array builtins, give these median batch-average costs per delivery:
  1 block: 1.600 -> 1.481 us; 20 blocks: 2.703 -> 2.219 us;
  200 blocks: 12.144 -> 8.892 us; 5,000 blocks: 238.828 -> 168.429 us;
  Four successive 200-block splices: 43.252 -> 31.229 us;
  Three 200-block bodies: 33.331 -> 24.177 us.
Mismatch fallback controls remain effectively unchanged: short length +0.1%,
long length unchanged. Valid workloads improve 7–29%. Runtime memory is capped
at 256 MiB; the Rust runner supplies a monotonic clock. The run took 8.32 seconds
with no competing owned job after an unrelated desktop spike settled. Ordinary
desktop activity remained around one CPU core; load was 3.71 on eight cores.
No app was interacted with or stopped. This excludes JSON decoding, bridge and
rendering; no end-to-end UI gain is claimed. Scope is plain decoded arrays and
objects, not custom species/getters. Evidence and all ten workload samples:
  target/performance-audit/chat-markdown-splice/{proof.log,timing.log,
