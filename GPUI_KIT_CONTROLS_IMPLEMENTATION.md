## Intentional custom/domain boundaries

* Input focus frames/background clicks are focus forwarding, not action buttons; InputState owns editing/caret/selection/clipboard/undo/IME. Modal pointer propagation boundaries only stop background activation. No migrated owner implements a competing EntityInputHandler; the legacy exported input macro stays compatible.
* File tree arrow expansion/selection, rooted file validation, preview background selection/native shortcuts, virtual list geometry, PDF loading and native Ghostty/terminal context behavior remain domain/native logic. The interactive toolbar/entry activation uses Base.
* Project/folder drag/drop and sidebar grouping, task/read-only detail text, tooltip anchors, decorative icons/switch knobs/swatches and native OS/layout surfaces remain custom/decorative. `file_preview.rs` has no standard click-only control needing replacement; its interactive host is FileExplorer/FilePreview.
* Automations destination/provider/scope/workspace/target choices intentionally remain Base Buttons rather than Radio: reselecting can invalidate/rebind a pinned target. First-run preset buttons recalculate time on each activation. Sort choices are Buttons because reselecting must dismiss the menu. These are meaningful commands with selected appearance, not a superficial role added to a Div.
* Pinned Base RadioGroup is an unstyled semantic container, not a built-in roving engine. Selected tab stops and the existing owner-managed arrow/circular navigation are retained; activation belongs solely to actual Base Radio/Button. No second Enter/Space engine remains.
* Native hover-revealed nested project actions retain the existing visibility policy. Keyboard visibility of those actions, dialog host native AX through the pinned focus-trap wrapper, SF-symbol/geometry/text-scale details and real OS clipboard/IME behavior need foundation/reviewer/parent native acceptance. The inert RiWork-theme fixtures do not establish those limits as passed.
* Whole Workspace/status/layout/pane-menu conversions remain foundation/parent-owned as inventoried. Chat copy diagnosis/fix remains chat/foundation-owned; this source commit makes no claim that chat copying is fixed.
