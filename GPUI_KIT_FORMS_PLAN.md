## Official documentation read and contract dependency

Read on 2026-10-06 from official GPUI Kit documentation. These live pages show v0.7.1 / main variants; their API is guidance, not a dependency pin. Baseline Cargo.toml uses `gpui-pre` and `gpui-pre-platform` **0.3.5**, Ghostty **0.3.1**, and has no Kit dependency. The Focus guide describes a newer GPUI snapshot. Foundation must supply compatible versions, import facade and root initialization before implementation.

- [Input](https://gpui-kit.com/component/input/): persistent `Entity<InputState>` passed to `Input::new`; Change, PressEnter (secondary), Focus and Blur events; single-line validation, disabled/readonly states and custom appearance. The docs warn that `set_value` resets undo and does not emit Change, so deliberate programmatic changes need application-side synchronization. Masked inputs restrict copy/cut. Exact behavior must be checked against the foundation pin.
- [Textarea](https://gpui-kit.com/component/textarea/): separate `TextareaState` for ordinary multiline content, retained in an entity; rows/auto-grow, soft wrapping and submit-on-enter policy. Use it for chat composer; the inventory's other fields keep their single-line semantics.
- [Focus](https://gpui-kit.com/docs/focus/): retain handles on owners; track them in the rendered tree; focus intentionally on entry. Exact focus and descendant containment have different purposes. Tab participation is explicit. Register focus subscriptions once. Overlay traps need entry and restoration logic as well as usable child targets.
- [Action](https://gpui-kit.com/docs/action/): shortcuts follow the focused element's dispatch path; match contexts and handlers to the intended owner. Account for propagation when an ancestor or global fallback must run.

Application-specific decisions below are migration proposals inferred from that guidance and baseline code, not claims that every API exists in the pending foundation.

## Persistent state strategy

- Each owning view creates library InputState/TextareaState once during construction or explicit editor/modal opening. Store entities, subscriptions and stable control identities on the owner. Render may rebuild library element builders; it must never create state/focus handles, subscribe, or reset values each frame.
- Constructors that currently accept only Context need an agreed Window-aware constructor or an explicit one-time initialization event. Prefer updating creation call sites over lazy per-render state creation. Schedule editor New/Edit creates entities when the editor opens; subsequent one-second refreshes retain them. Cancel/close releases editor state and subscriptions.
- Treat the library value as the editing source of truth. Read fresh values on submit. Domain snapshots may contain Strings, but never push a mirror back into the editing state on each render/refresh. Keep pure schedule binding/timing data separate from UI entities if needed so reviewed domain tests remain headless.
- Subscribe once to Change for existing effects: save-status/error updates, name/path inspection, filter selection, quick-time clearing and draft updates. Focus/Blur updates the active field and styling without stealing focus back. Store subscriptions for precisely the owner's lifetime; dynamic editors must release old subscriptions.
- Programmatic reset/selection occurs only for New/Edit initialization, successful save, intentional model suggestion, browse, quick-time preset, explicit root/project switch, or baseline external-name refresh when the draft was untouched. Do not erase selections, composition or undo for ordinary refresh/theme changes. Account/folder choice updates must retain unrelated drafts.
- Workspace has one canonical query but can show searches in multiple tabs/panes. Do not attach one library input entity to multiple concurrent editing geometries without documented support. Proposed approach: retain per-surface InputState entities keyed by stable TabId, share query changes through Workspace, update inactive states only on actual query changes, and focus only the active surface. Guard against synchronization loops and preserve active composition. An alternative single mounted editing surface requires parent agreement; repeated rendered inputs cannot allocate state every frame.
- ProjectSettings and Automations currently use ordinal Field/Control navigation. Map library focus to stable field/control identity; keep hidden model/effort/date/minute drafts while excluding hidden/disabled fields from navigation. When dynamic target/account lists change, retain identity rather than a stale index.

## Keyboard, IME, focus and validation preservation

- Library editing owns caret, selection, word movement, Shift selection, delete, clipboard, undo/redo, graphemes, IME and hit-testing. Remove migrated custom caret glyphs, canvas input registration and form EntityInputHandler implementations; do not recreate them in an adapter. Preserve text-size/theme styling through the foundation's presentation contract.
- Keep form-specific Enter, Escape, Cmd+S and navigation in the appropriate dispatch path. Prefer input events/actions; Enter used to accept IME candidates must not submit, save, activate a search hit or hand off. Check the pinned Kit guarantee and test it. Avoid duplicate parent key handling plus input PressEnter callbacks.
- Existing paste policies differ: shared helper collapses newline runs to spaces and drops outer breaks (including CRLF/NEL/Unicode separators); ProjectCreator and FileExplorer remove CR/LF; Workspace converts CR/LF to spaces; chat normalizes multiline separators to LF. Capture those policies in the foundation facade or an approved non-editing text normalization hook. Do not silently switch prompt/note to multiline or strip internal spaces. Test Unicode offsets and marked text rather than copying legacy range arithmetic.
- Workspace currently clears `search_focused` during render when its own handle lacks exact focus (`main.rs:9989`). Replace this with the active library input's focus/Blur lifecycle; merely using containment for all Workspace descendants would incorrectly count a terminal as search. Preserve `focus_active` terminal/panel routing, modal gates, menu Escape priorities, drag cancellation and native terminal freeze/thaw behavior.
- Retain Workspace `search_key_down`'s terminal text-size suppression and existing context-sensitive Bigger/Smaller/Actual Size bindings (`main.rs:7358`, `:11180`). Library editing must not consume terminal keystrokes while a terminal owns focus. Do not widen global bindings or change menus during a search migration.
- Preserve the current navigation order for both Tab directions across text fields and non-text controls. Choose one navigation owner per region: either approved Kit/root navigation with mapped controls or retained application traversal that explicitly focuses the next library field. Do not let both process Tab. Save prior focus on modal entry and restore a current target on dismiss; the existing fallback is Workspace's active pane. Focus only on intentional entry, not rendering.
- Keep validation on the existing domain boundary, including temporarily invalid drafts. A typed partial ISO timestamp, empty optional option or partially edited path must remain editable. Do not replace current store validation with keystroke-rejecting numeric/mask validation. Preserve disabled/pending gates, visible errors, trimmed optional values and successful-save events.
- RemotePrompt's secret display is currently a transient masked rendering clone over real state. A replacement must conceal the real value without introducing per-render state or logging it. Check library masking/clipboard behavior with inert synthetic text; do not expose a reveal control by default. Preserve useful non-secret feedback within the approved foundation contract.
